{%- comment -%} ============================================================================ 这一块负责把「评论数」真正填到卡片的 CUSTOM-4 空壳里。 ---------------------------------------------------------------------------- 为什么不能像浏览量那样构建时直接印死？ 浏览量来自 _data/views.json（一个自己维护的数据文件），构建时就知道数字； 评论数存在评论服务（Twikoo）的数据库里，构建时网站根本连不上它， 所以只能等访客打开页面后，由浏览器去问一次。 【只发 1 个请求，不是每张卡片各发一个】 把本页 10 篇文章的网址打包成一份清单，一次性问后端： 「这 10 个网址各有多少条评论？」 后端一次返回 10 个数字，脚本再分别填回各张卡片。 —— 如果每张卡片各发一个请求，一页就是 10 次往返， 既慢又会白白消耗评论服务的调用额度。 【三种情况都不显示，绝不出现假数字】 ① 网络不通 / 请求超时（8 秒） ② 后端返回的格式不对 ③ 后端这次没返回这篇文章的数字 以上任何一种，卡片上就保持「不显示评论数」，宁可少一个数字，也不显示错的。 【⚠️ 内联脚本禁用 `//` 行注释】 _config.yml 开着 compress_html，正式构建会把换行全部压掉， 用 `//` 写注释会把后面的代码一并注释掉，导致整页脚本报错。 本段一律使用 /* 星号斜杠 */，语句结尾都带分号。 ============================================================================ {%- endcomment -%} {%- comment -%} 与 CUSTOM-4 是同一个总开关，这里再读一次： 不依赖上面那个 for 循环是否执行过（本页一篇文章都没有时循环不会跑）。 {%- endcomment -%} {%- if site.commentcount -%} {%- assign _cc_provider = site.commentcount.provider | default: '' | strip -%} {%- else -%} {%- assign _cc_provider = 'twikoo' -%} {%- endif -%} {%- assign _cc_env = site.comments.twikoo.env_id | default: '' | strip -%} {%- comment -%} 评论数是否包括「回复」： false（默认）= 只数顶层留言，一张卡片显示「3」，读者理解为「3 个人留言」； true = 连回复一起数，数字会更大，好处是和文章底部评论区的 「共 N 条」完全一致。 【可DIY修改】在 _config.yml 的 commentcount.include_reply 里改，不用动这里。 {%- endcomment -%} {%- assign _cc_reply = site.commentcount.include_reply -%} {%- if _cc_reply == true -%} {%- assign _cc_reply = true -%} {%- else -%} {%- assign _cc_reply = false -%} {%- endif -%} {%- if _cc_provider == 'twikoo' and site.comments.provider == 'twikoo' and _cc_env != '' -%} {%- endif -%} {%- comment -%} 如果总页数超过 1 页，就在底部显示翻页按钮（上一页 / 页码 / 下一页）。 {%- endcomment -%} {% if paginator.total_pages > 1 %} {% include post-paginator.html %} {% endif %}
