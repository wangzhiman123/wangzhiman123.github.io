{%- comment -%} ============================================================================ 本文件是什么？ ---------------------------------------------------------------------------- 这是「友情链接」板块的渲染组件。前台任何位置想显示友链，都用一行 {% include friend-links.html %} 调用它即可，不必重复写渲染代码。 · 数据源：_data/links.yml —— 全站唯一一份友链数据 · 渲染方式：构建时由 Liquid 静态生成 HTML，前端零请求、零闪烁 ============================================================================ ⚠️【铁律一：卡片本体必须是
，绝不能是 】——踩过的坑，别改回去 ---------------------------------------------------------------------------- 早期版本把整张卡片写成 ，又在卡片内部放了第二个 链接，于是构成 **非法的 套 嵌套**：HTML 解析器遇到内层 就会把 外层 提前闭合，内层链接被甩到卡片外面，变成散落在网格里的孤立条目。 现在的做法（标准的「stretched link」模式）： · 外层
—— 只负责排版，不是链接 · 卡片名称包一层真链接 ， 用 ::after 伪元素铺满整张卡片 —— 整卡可点，语义仍是真链接 ★ 2026-10-15：卡片内原有的「邮件联系 / RSS 订阅」两个入口已按需求移除， 所以现在卡片内只有「站点名」一个链接。容器仍保持
—— 以后若要加回任何第二个链接， 套 的老问题会立刻重现。 ============================================================================ ⚠️【铁律二：图标有自定义 logo 时绝不输出首字文字】——别改回去 ---------------------------------------------------------------------------- 里的文字和 background-image 是同一个元素的两层。 如果「配了 logo 也照样输出首字」，那么： · PNG/SVG 图标带透明背景时 → 首字从透明处透出来，文字和图标**叠在一起**； · 图标加载失败时 → 文字出现（这本来是我们想要的兜底）； 两个目标混在一起，结果就是「图标与文字重复显示」。 所以这里用 if/else 二选一： 有 logo → 只输出背景图，一个字都不输出； 无 logo → 只输出首字文字，不输出 background-image。 加载失败时的兜底仍靠 background-color 兜住（不会是空白）。 ============================================================================ ⚠️【铁律三：图标不用 ，用 + 背景图】 ---------------------------------------------------------------------------- 1. jekyll-theme-chirpy v7.6 会在构建时自动把页面里的 包装成 …，与卡片布局打架。 2. shimmer 的 CSS 会给图片设宽高并加骨架屏动画，直接覆盖 .fl-logo 的尺寸。 3. 图片加载失败时 shimmer 会一直停在骨架屏动画状态 —— 就是"永远加载中"。 所以：图标一律用 纯 CSS 背景图实现。主题不碰 ，上面三个问题同时消失。
