{%- comment -%} ============================================================ 【本文件是什么？】 阅读量统计 · 统一数据源版 v7 ------------------------------------------------------------ 用途：覆盖 Chirpy 主题自带的 _includes/pageviews/goatcounter.html （该文件被主题注入在 中，早于 里的 #pageviews 元素， 所以下面的脚本必须等 DOM 就绪后再填充） 一句话概括：这段代码负责把「这篇文章被看了多少次」这个数字， 填到文章页的"X 次浏览"位置上。数字本身是提前算好、写在网页里的， 不靠访客的浏览器去外面请求，所以打开速度不受影响、也不会一直转圈。 ！！本文件里绝对不能出现 // 行注释 —— 这是 v6 失效的原因！！ ------------------------------------------------------------ _config.yml 开启了 compress_html，生产构建会把整份 HTML 的换行 全部压掉（线上页面实测 0 个换行）。一旦代码里出现 // 行注释， 它会把「本行之后」的所有代码一路注释到脚本结尾： (function () { "use strict"; // 注释... var raw = 12; ... 全部变注释 结果 IIFE 变成空函数，数字填不进去，文章页就永远转圈。 所以本文件的铁律（Chirpy 主题自带的内联脚本也是这么写的）： ① 注释一律用 /* */ 块注释，禁用 // ② 每条语句都以 ; 结尾，不依赖 JavaScript 的自动分号补全 ③ 判断分支一律带花括号，压缩掉空白后语义不变 ------------------------------------------------------------ 数值来源：_data/views.json（构建时静态渲染） 与首页卡片共用同一份数据，两处数值永远一致； 显示过程不发任何网络请求，所以永远不会转圈、也不会出现假数字。 计数方式：仍异步触发一次「不蒜子」接口（仅统计用，返回值不参与显示）。 该接口每被调用一次就会让该页 +1，因此定时脚本用 _data/pv_state.json 做了「轮询补偿」，详见 scripts/update_views.py。 ============================================================ {%- endcomment -%} {%- if page.layout == 'post' -%} {# 只有在"文章详情页"才需要显示浏览量，其他页面（首页、关于页等）不加载这段脚本， 好处是能少加载一点代码、页面更快。 #} {%- assign pv = site.data.views[page.url] | default: 0 -%} {# 从 _data/views.json 里按当前网页的网址取出这篇文章的浏览量。 万一没有记录，就当作 0（default: 0 兜底，避免报错）。 #} {%- endif -%}
